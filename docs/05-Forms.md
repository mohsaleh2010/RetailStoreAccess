## 2. تصميم الواجهة

| العنصر | القرار |
|---|---|
| الاتجاه | كل الشاشات من اليمين لليسار (`Orientation = Right-to-Left`) |
| الخط | Segoe UI (يدعم العربية)، والأيقونات من خط Segoe MDL2 Assets المدمج في Windows 10/11 |
| الألوان | كحلي `#1F3A5F` للعناوين والقائمة، أخضر مزرق `#0E7C70` لزر الحفظ، أحمر `#B03A2E` للحذف، رمادي فاتح للخلفية، رمادي للحقول المقفلة |
| الأزرار | كبيرة، بلون يتغير عند المرور بالماوس (Access 2010+)، وتظهر يد عند المرور |
| الحقول الإلزامية | عليها علامة `*`، وتظهر رسالة عربية تذكر اسم الحقل إن تُركت فارغة |
| الحقول المحسوبة | مقفلة بلون رمادي: الكمية، متوسط التكلفة، الرصيد الحالي، إجمالي المصروف |
| إخفاء Access | لا شريط أدوات، ولا جزء تنقل، ولا قوائم مختصرة، ولا F11 (في وضع المستخدم) |

### اختصارات لوحة المفاتيح
| المفتاح | الوظيفة |
|---|---|
| `Ctrl + S` | حفظ |
| `F2` | سجل جديد |
| `F3` | الانتقال لمربع البحث |
| `Esc` | إغلاق الشاشة (مع سؤال عن الحفظ إن وُجدت تعديلات) |
| `Enter` | الانتقال للحقل التالي |

### قواعد العمل المطبقة في الشاشات
| الشاشة | القاعدة |
|---|---|
| المنتجات | كود تلقائي `P00001` إذا تُرك فارغًا؛ لا تكرار للكود ولا للباركود؛ متوسط التكلفة لمنتج جديد = سعر الشراء؛ **الكمية لا تُعدَّل يدويًا**؛ تحذير إذا كان سعر البيع أقل من التكلفة |
| العملاء والموردون | **الرصيد الافتتاحي يُقفل بعد أول عملية**، والرصيد الحالي = الافتتاحي ما دامت لا توجد عمليات (مطابق لفحص السلامة)؛ تحذير لجوال بغير الصيغة السعودية؛ رفض بريد إلكتروني غير صحيح؛ "عميل نقدي" لا يُحذف ولا يُعطَّل ولا يُسمح له بالآجل |
| المصروفات | رقم تلقائي `EXP-000001`؛ الإجمالي = المبلغ + الضريبة؛ الموظف الحالي يُسجَّل تلقائيًا؛ تحذير للتاريخ المستقبلي |
| الإعدادات | تحذير إذا كان الرقم الضريبي فارغًا، أو كانت نسبة الضريبة غير 15% |
| الحذف (كل الشاشات) | سجل غير مستخدم يُحذف بعد التأكيد؛ **السجل المستخدم في عمليات يُعرض تعطيله بدل حذفه** فيختفي من القوائم ويبقى في التقارير |

### مركز التقارير
21 تقريرًا: التقارير الـ 16 المطلوبة، والضريبة، وأرصدة العملاء والموردين، وفحص السلامة. عند اختيار تقرير تتفعّل فقط الحقول التي يحتاجها. مثلًا: "كشف حساب عميل" يفعّل الفترة والعميل، و"المخزون الحالي" لا يفعّل شيئًا. وتوجد أزرار فترة سريعة: اليوم، هذا الشهر، الشهر الماضي، هذه السنة.

## 3. طريقة التشغيل

> المتطلب: المراحل 2–4 منفّذة.

1. افتح `RetailStore_FE.accdb`، واضغط **Alt + F11**، ثم استورد من `dist/vba/` بهذا الترتيب (**File ← Import File**):
   1. `modCommon.bas`
   2. `modStartup.bas`
   3. `modForms.bas`
   4. `modScreens.bas`
   5. `modAppData.bas`
   6. `modBuildForms.bas`
2. **Debug ← Compile RetailStore_FE**. يجب ألا تظهر أي رسالة.
3. في نافذة **Immediate** (**Ctrl + G**):
   ```
   BuildForms
   ```
   **النتيجة المتوقعة:** "تم بناء الشاشات بنجاح (11 شاشة)". تستغرق البناء بضع ثوانٍ والشاشة متوقفة عن التحديث.
4. ثم:
   ```
   TestForms
   ```
   **النتيجة المتوقعة:** "جميع اختبارات الشاشات ناجحة (46 اختبارًا)".
5. افتح `frmMain` من جزء التنقل، وجرّب الشاشات.

### وضع المستخدم النهائي (إخفاء أدوات Access)
عندما تكون جاهزًا لتسليم النظام لموظفي المحل:
```
InstallUserMode
```
ثم أغلق الملف وافتحه من جديد. سيفتح على `frmMain` مباشرة، بدون شريط أدوات وبدون جزء تنقل.

**للعودة للتطوير:** اضغط مع الاستمرار على **Shift** أثناء فتح الملف، ثم شغّل `InstallDeveloperMode`.
(قفل مفتاح Shift نهائيًا جزء من نظام الصلاحيات في المرحلة 10.)

## 4. طريقة الاختبار

### 4.1 الاختبار الآلي داخل Access: `TestForms` (46 اختبارًا)
**يعمل عبر الشاشات نفسها**، أي يفتحها مخفية ويكتب في حقولها ويضغط أزرارها برمجيًا. ثم يحذف كل بيانات الاختبار ويعيد عدّادات الترقيم كما كانت.

| المجموعة | ما يُختبر |
|---|---|
| فتح الشاشات (11) | كل شاشة تفتح، وكل قائمة منسدلة وقائمة سجلات فيها تعمل |
| دوال مساعدة (6) | `RoundMoney(2.345) = 2.35`، الأرقام السالبة، تهريب نص البحث، صيغة التاريخ في SQL |

| العملاء (6) | رفض بريد خاطئ، رصيد افتتاحي = رصيد حالي، مطابقة فحص السلامة، فتح الشاشة على سجل محدد، **منع حذف العميل النقدي** |
| المصروفات (4) | حساب الضريبة 15%، الحفظ، الترقيم `EXP-######`، تسجيل الموظف |
| البحث (8) | الأنواع الخمسة تعمل، البحث بالباركود، بجزء من الاسم، برقم الجوال |
| مركز التقارير (4) | كل استعلامات التقارير موجودة، عدد التقارير، تفعيل الحقول المناسبة لكل تقرير |

### 4.3 الاختبارات الآلية في المستودع (للمطوّر)
```
python3 tools/generate.py
python3 -m unittest discover -s tests -v      # 144 اختبارًا (المراحل 2–5)
```
اختبارات المرحلة 5 (65 اختبارًا):
- **الشكل:** كل عنصر داخل حدود الشاشة؛ لا تداخل بين الحقول والأزرار؛ كل الشاشات تتسع لشاشة 1366×768.
- **الربط:** كل حدث مضبوط على `[Event Procedure]` له إجراء بنفس الاسم، والعكس، بالتوقيع الصحيح (مثل `Cancel As Integer`).
- **الحقول:** كل حقل مربوط موجود في جدوله؛ كل حقل إلزامي بدون قيمة افتراضية موجود على الشاشة؛ كل `frm!Field` يستخدمه الكود موجود فعلًا.
- **SQL:** كل قائمة منسدلة، وقائمة سجلات، وقالب بحث تُنفَّذ على نسخة SQLite مع بيانات الاختبار، بنتائج محددة. مثال: البحث عن "TEST-INV-2" يعيد تلك الفاتورة فقط، والبحث بفترة آخر 7 أيام يعيد فاتورة واحدة.
- **مركز التقارير:** معاملات كل تقرير تطابق معاملات استعلامه؛ عمود التصفية بالتاريخ موجود فعلًا في نتيجة الاستعلام.
- **على مستوى المشروع كله (كل الوحدات):** كل إجراء يُستدعى موجود؛ لا تكرار لأسماء الإجراءات العامة؛ **لا متغير محلي يحمل اسم إجراء**؛ لا إجراء يتجاوز حد 64KB الذي يفرضه Access.

## 6. قيود معروفة (أحتاج ملاحظتك عليها)

1. **الاتجاه:** في الشاشات من اليمين لليسار، يقيس Access موضع العنصر من **الحافة اليمنى**، وهذا ما بنيت عليه. لم أستطع التأكد من ذلك بالتشغيل. إن ظهرت معكوسة فالحل تغيير سطر واحد (القسم 4.2).
2. **الأيقونات** تحتاج Windows 10 أو 11 (خط Segoe MDL2 Assets). على Windows 7 تظهر مربعات، لكن الأزرار تبقى تعمل ونصها واضح.
3. **ألوان الأزرار عند المرور** تحتاج Access 2010 أو أحدث. في النسخ الأقدم تظهر الأزرار بالشكل الافتراضي، ويُسجَّل تنبيه في نافذة Immediate بدل التوقف.
4. **الشاشات مولَّدة:** أي تعديل يدوي عليها يُفقد عند تشغيل `BuildForms` مرة أخرى. التعديلات تتم في `tools/forms.py` ثم يُعاد التوليد. أخبرني بما تريد تغييره وأعدّله.
5. **الصلاحيات:** كل الأزرار متاحة لكل المستخدمين حتى المرحلة 10. الدالة `HasPermission` موجودة ومستخدمة، وستُفعَّل حينها.

**المرحلة 6: نظام المبيعات (نقطة البيع POS)**، وتشمل:
- شاشة بيع سريعة: إدخال بالباركود، بحث بالاسم، تعديل الكمية، حذف سطر، خصم على السطر والفاتورة، ضريبة 15%، عميل، طريقة دفع، المدفوع والباقي.
- **حفظ الفاتورة في معاملة واحدة:** رقم تسلسلي، أسطر، حركات مخزون، تحديث الكميات والأرصدة. مع منع البيع بأكثر من المتوفر إلا بإذن المدير.
- **متطلبات الضريبة السعودية:** فاتورة مبسطة أو ضريبية، الرقم الضريبي، والضريبة منفصلة.
- **رمز QR بصيغة TLV/Base64** للمرحلة الأولى من فاتورة، مع اختباره على قيم معروفة.
- طباعة الفاتورة (حراري 80 مم و A4).
- مرتجعات المبيعات (إشعار دائن).
