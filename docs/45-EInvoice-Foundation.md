# أساس الفاتورة الإلكترونية (مشترك بين السعودية ومصر)

**الفكرة:** هذه المرحلة «ب» من الخطة (`docs/43-Plan-EInvoicing-SA-EG.md`). تبني ما تحتاجه الدولتان قبل منظومة كل دولة:
- حالة إرسال لكل فاتورة بيع ومرتجع؛
- سجل لكل طلب وردّه؛
- الاتصال بالإنترنت وقراءة الردود؛
- شاشة متابعة وإعادة إرسال؛
- التفعيل واختيار البيئة.

**منظومة كل دولة وحدة مستقلة تُضاف لاحقًا:** السعودية في المرحلة «ج»، ومصر في المرحلة «د». تتصل كلتاهما بهذا الأساس دون تعديله. لذلك **لا يُرسل شيء فعليًا في هذه المرحلة**، والتفعيل يُرفض حتى تُثبَّت منظومة الدولة.

## 1) حالة الفاتورة الإلكترونية لكل مستند
| الحالة | المعنى |
|---|---|
| لا يُرسل (`NOT_SENT`) | حُفظ قبل تفعيل الفاتورة الإلكترونية |
| بانتظار الإرسال (`PENDING`) | حُفظ بعد التفعيل ولم يُقبل بعد |
| مُبلَّغ (`REPORTED`) | السعودية: فاتورة مبسطة أُبلغت للهيئة |
| معتمد (`CLEARED`) | السعودية: فاتورة ضريبية اعتمدتها الهيئة |
| مُرسل (`SUBMITTED`) | مصر: أُرسل وينتظر تحقق المصلحة |
| صالح / غير صالح (`VALID` / `INVALID`) | مصر: نتيجة التحقق |
| مقبول مع تحذير (`WARNING`) | قُبل مع ملاحظة تُصلح في المستندات التالية |
| مرفوض (`REJECTED`) | لم يُقبل، والسبب في سجل الإرسال |

**لكل مستند أيضًا:** عدد محاولات الإرسال، وآخر خطأ.

## 2) الإرسال
- **بعد حفظ الفاتورة أو المرتجع مباشرة:** إن كانت الفاتورة الإلكترونية مفعّلة والمنظومة جاهزة، يُرسل المستند فورًا.
  - إن فشل الإرسال (انقطاع الإنترنت مثلًا) يبقى المستند «بانتظار الإرسال». **البيع لا يتوقف ولا يفشل.**
- **من شاشة المتابعة:**
  - «إرسال المختار» لمستند واحد، ويصلح لإعادة إرسال المرفوض بعد تصحيح سببه؛
  - «إرسال كل المعلّق» بالترتيب من الأقدم. يتوقف عند أول انقطاع للإنترنت، لأن ما بعده سيفشل أيضًا.
- **تنبيه:** عدد المستندات التي ما زالت «بانتظار الإرسال» بعد 20 ساعة يظهر بالأحمر، لأن مهلة تبليغ الفاتورة المبسطة في السعودية 24 ساعة.

## 3) شاشة الفاتورة الإلكترونية
**أين:** الإعدادات ← زر **«الفاتورة الإلكترونية»** بجانب دولة التشغيل. صلاحيتها الجديدة: «الفاتورة الإلكترونية: المتابعة وإعادة الإرسال».

| الجزء | ما فيه |
|---|---|
| **الفترة والمستندات** | تحتاج متابعة (بانتظار الإرسال، مرفوضة، تحذير)، أو أُرسلت، أو قبل التفعيل، أو الكل |
| **البيئة** | تجريبية، أو محاكاة (للسعودية)، أو فعلية |
| **تفعيل الإرسال** | يحتاج صلاحية إعدادات المحل، ويُرفض حتى تُثبَّت منظومة الدولة. يُسجَّل في سجل التدقيق |
| **السطر الأعلى** | المنظومة، والبيئة، وعدد المستندات، والمتأخرة |
| **القائمة** | الرقم، والتاريخ، والنوع، والعميل، والإجمالي، والحالة، والمحاولات، وآخر خطأ |
| **أسفل الشاشة** | طلبات المستند المختار وردود المنظومة |

## 4) سجل الإرسال (`EInvoiceLog`)
لكل طلب للمنظومة سطر يحتوي:
- الوقت، والدولة، والمستند، والعملية (إرسال، استعلام، دخول، تسجيل جهاز)، والعنوان؛
- رمز الرد، والنتيجة، والرسالة؛
- **الطلب والرد كاملين**، للمراجعة وللرد على أي استفسار من الجهة الحكومية.

## 5) للمطوّر
| الملف | ما فيه |
|---|---|
| `src/vba/modEInvoice.bas` | `EInvoiceEnabled`، `EInvoicePlatform`، `EInvoiceReadyProblem`، `SendEInvoice`، `SendPendingEInvoices`، `EInvoiceAfterSave`، `SetEInvoiceStatus`، `LogEInvoice`، `EInvoiceOverdueCount`، الشاشة، واختبار `TestEInvoice` |
| `src/vba/modHttp.bas` | `HttpSend` (عبر `MSXML2.ServerXMLHTTP.6.0`، والنص بترميز UTF-8)، و`JsonGet` (قيمة من رد JSON بمسارها، مثل `validationResults.warningMessages[0].code`)، و`JsonEscape` |
| `tools/json_reference.py` | النسخة المكتوبة بـ Python من `JsonGet` و`JsonEscape` |
| `qryEInvoiceDocs` | الفواتير والمرتجعات وحالتها في استعلام واحد |

**منظومة الدولة:** وحدة فيها دالتان عامتان، تستدعيهما `modEInvoice` بالاسم عبر `Application.Run`:

| الدولة | الدالتان |
|---|---|
| السعودية | `ZatcaReadyProblem()` و`ZatcaSendDocument(DocKind, DocID)` |
| مصر | `EtaReadyProblem()` و`EtaSendDocument(DocKind, DocID)` |

- `…ReadyProblem` ترجع "" حين تكون الشهادة أو بيانات الدخول جاهزة.
- `…SendDocument` ترجع `"النتيجة|الرسالة"`، والنتيجة: `OK` أو `WARNING` أو `REJECTED` أو `ERROR` أو `NETWORK`. وتستخدم `SetEInvoiceStatus` و`LogEInvoice`.

**ما تغيّر في البيانات:**
- **الحالات المسموحة** في `ZatcaStatus` زادت لتشمل حالات مصر. `BuildSchema` يحدّثها في ملف بيانات موجود (`RULE_UPGRADES`).
- **حقول جديدة:**
  - `Settings.EInvoiceEnabled` و`EInvoiceEnvironment`؛
  - `EInvoiceAttempts` و`EInvoiceError` على الفواتير والمرتجعات.
- **الحقل القديم `ZatcaEnvironment` لم يعد مستخدمًا.**
- **جدول السجل بلا علاقة:** `EInvoiceLog` يشير إلى فاتورة أو مرتجع حسب `DocKind`، فلا يُربط بعلاقة.

## 6) الاختبارات
`tests/test_einvoice.py`:
- **قراءة JSON:** النسخة المكتوبة بـ Python تُقارن بمكتبة `json`، ونسخة VBA في LibreOffice تُقارن بالنسخة المكتوبة بـ Python. تشمل:
  - نصوصًا عربية وعلامات تنصيص ورموزًا؛
  - مصفوفات متداخلة، ومسارات غير موجودة، وقيمًا فارغة.
- **الإرسال:**
  - قراءة نتيجة المنظومة؛
  - الحالات على الجدولين وفي ملف بيانات موجود؛
  - استدعاء منظومة الدولة بالاسم بعد فحص التفعيل والجاهزية؛
  - الإرسال بعد البيع لا يُفشل البيع.
- **الشاشة والتفعيل:**
  - استعلام المستندات يعمل ويعرض أسماء الحالات؛
  - التفعيل يحتاج الصلاحية والجاهزية، ويُسجَّل في سجل التدقيق.

**داخل Access:** `TestEInvoice` (ضمن `RunAllTests`) يفحص، داخل معاملة تُلغى:
- قراءة JSON؛
- رفض الإرسال قبل التفعيل؛
- تغيير الحالة؛
- سطر السجل برقم المستند؛
- تنبيه المتأخر.

## 7) التثبيت والاختبار
1. **استورد الوحدتين الجديدتين** `modHttp` و`modEInvoice`.
2. **استبدل** `modSales` و`modZatca` و`modForms` و`modTestAll` والوحدات المولَّدة (الصف 41 في `README.md`). أو أعد البناء بـ `BuildFrontEnd.vbs`.
3. شغّل بالترتيب: `BuildSchema` ← `BuildRelations` ← `BuildQueries` ← `BuildForms`.
4. شغّل `RunAllTests`، وفيه `TestEInvoice`.
5. **الاختبار اليدوي:**
   1. افتح الإعدادات ← «الفاتورة الإلكترونية». تظهر فواتيرك بحالة «لا يُرسل» عند اختيار «قبل التفعيل».
   2. جرّب «تفعيل الإرسال». يجب أن يرفض البرنامج برسالة «ربط … لم يُثبَّت بعد»، لأن منظومة الدولة تأتي في المرحلة التالية.
   3. غيّر البيئة، ثم افتح سجل التدقيق: يظهر التعديل.
