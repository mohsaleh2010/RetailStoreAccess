# الشاشات (Forms): كيف تُبنى وكيف تعمل

**قائمة كل الشاشات** مع الجدول والصلاحية ومن أين تُفتح موجودة في [Screens-Index.md](Screens-Index.md)، وهي مولَّدة تلقائيًا.

## 1) من أين تأتي الشاشة
لا تُرسم أي شاشة يدويًا في Access. خطوات صنعها:
1. **التعريف في Python:** في `tools/forms.py` أو `tools/forms_*.py`، تُعرَّف الشاشة كـ `FormModel`. هو قائمة عناصر `Control`، لكل عنصر نوع وموضع ومقاس وخصائص وأحداث.
2. **التوليد:** `tools/gen_forms.py` يحوّل كل نموذج إلى إجراء `BuildForm_<name>` داخل `modBuildForms`.
3. **البناء:** الإجراء يستدعي `CreateForm` و`CreateControl` في Access، ثم يكتب كود الشاشة، وهو أسطر قصيرة تستدعي الوحدات العامة.
4. **التشغيل:** `BuildForms` يحذف كل الشاشات ويعيد بناءها. أي تعديل يدوي داخل Access يضيع.

**الوحدات والمقاسات:**
- المقاسات بالسنتيمتر: `cm(2.4)`، وتتحول إلى twips.
- كل الشاشات تُصمَّم من اليمين لليسار. في ملف واجهة إنجليزي يبنيها `BuildForms` من اليسار لليمين (`Orientation = 0`) ويعكس أماكن العناصر، ويترجم كل نص بـ `Tr` (`docs/38-English-Interface.md`).
- الخط والألوان ثابتة في `modCommon`: `CLR_PRIMARY` و`CLR_ACCENT`...

## 2) أنواع الشاشات
| النوع | كيف تُعرَّف | أمثلة |
|---|---|---|
| **شاشة بيانات (قائمة + تفاصيل)** | `DataScreen` في `DATA_SCREENS` داخل `tools/forms.py`. البحث والقائمة على اليمين، والحقول على اليسار، وأزرار جديد وحفظ وتراجع وحذف | المنتجات، العملاء، المصروفات، المستخدمون، المصروفات المتكررة |
| **شاشة مسير (مسودة ثم ترحيل)** | رأس غير مربوط + شبكة فرعية على الأسطر، مثل `forms_payroll.py` و`forms_sales_reps.py` | الرواتب، عمولات المندوبين |
| **شاشة سجل واحد** | `DataScreen(kind="SINGLE")` | الإعدادات |
| **شاشة مستند أو عمليات** | دالة `layout_x()` في `forms_*.py`، وعناصرها غير مربوطة بجدول. الحفظ بكود في وحدة مختصة | نقطة البيع، الشراء، السندات، الرواتب، سجل التدقيق |
| **شاشة فرعية (شبكة)** | `FormModel` مربوط بجدول، وعرضه «متصل» (`DefaultView = 1`)، وأعمدته من `grid_row` | أسطر الموازنة، أسطر الرواتب، أسطر نقطة البيع |
| **شاشة مربعات (لوحة)** | مستطيل وأيقونة ونص، وفوقها زر شفاف | الشاشة الرئيسية `frmMain`، شاشة المحاسبة `frmAccounting` |

## 3) شاشات البيانات: خاصية Tag
كل شاشة بيانات تحمل إعداداتها في خاصية **Tag**، وكل الشاشات تشترك في كود واحد هو `modForms`. مثال:

```
KIND=LIST|TABLE=Products|PK=ProductID|LIST=SELECT ...|SEARCH=t.ProductName,t.Barcode
|ACTIVE=t.IsActive|SEQ=PRODUCT_CODE:ProductCode|UNIQUE=ProductCode,Barcode
```

| المفتاح | المعنى |
|---|---|
| `KIND` | `LIST` أو `SINGLE` |
| `TABLE` / `PK` | الجدول ومفتاحه |
| `LIST` | استعلام القائمة. `{ACTIVE}` و`{SEARCH}` يُستبدلان بالشروط |
| `SEARCH` | الحقول التي يبحث فيها مربع البحث |
| `ACTIVE` | حقل «نشط». مربع «إظهار غير النشط» يعتمد عليه |
| `SEQ` | ترقيم تلقائي عند الحفظ: `اسم العدّاد:الحقل` |
| `UNIQUE` | حقول يُمنع تكرارها، برسالة عربية قبل الحفظ |

**الأحداث العامة في `modForms`:**

| الحدث | ماذا يفعل |
|---|---|
| `FormLoad` | يطبّق الصلاحيات (الإضافة والتعديل والحذف)، ويملأ القائمة |
| `FormCurrent` | يحدّث القائمة والحالة، ومعالجة خاصة لكل جدول (`Case "Products"`...) |
| `FormBeforeUpdate` | الترتيب: صلاحية الحفظ، ثم الفترة المقفلة، ثم الحقول المطلوبة، ثم تحقق خاص بكل جدول (`ValidateExpense` و`ValidateRecurring`...)، ثم منع التكرار، ثم الترقيم، ثم **تسجيل التدقيق** `AuditFormBefore` |
| `FormAfterUpdate` | يكتب سجل التدقيق `AuditFormAfter`، ويحدّث القائمة |
| `DeleteRecord` | الصلاحية، والفترة المقفلة، والسجلات الأساسية، والتأكيد، ولقطة السجل للتدقيق، ثم الحذف |
| `FieldChanged` | حساب فوري عند تغيير حقل، مثل الإجمالي = المبلغ + الضريبة |

**مهم:** إذا عملت شاشتان على جدول واحد (مثل `frmUsers` و`frmEmployeePay` على `Employees`)، يجب أن تفحص المعالجة الخاصة اسم الشاشة `frm.Name`. يوجد اختبار يفرض ذلك.

## 4) تسمية العناصر
| البادئة | العنصر |
|---|---|
| `txt` | مربع نص غير مربوط |
| `cbo` | قائمة منسدلة |
| `lst` | قائمة |
| `btn` | زر |
| `lbl` | عنوان. `lbl` + اسم الحقل هو عنوان الحقل، ويُستخدم أيضًا في سجل التدقيق |
| `chk` | مربع اختيار |
| `box` | مستطيل |
| `ico` | أيقونة بخط Segoe MDL2 |

- **العناصر المربوطة بحقل** تحمل اسم الحقل نفسه، مثل `ExpenseDate`. لذلك يكتب الكود `frm!ExpenseDate`.
- **في الشاشة الفرعية** يصل الكود إلى حقول السجل بـ `Me!Field`.

## 5) قواعد الشكل (كل قاعدة سببها خطأ حقيقي)
- **مربع الاختيار** ليس له لون خلفية `BackColor`. لا تعيّن خاصية لا يملكها نوع العنصر، وإلا ظهر الخطأ 438. يوجد اختبار لذلك.
- **الزر يُرسم فوق العنوان أو الأيقونة** الموضوعة عليه عند التركيز أو مرور المؤشر. الحل: الأيقونة والنص كعنصرين مستقلين، وفوقهما زر **شفاف** (`Transparent`). هكذا بُنيت القائمة الجانبية والمربعات.
- **لا تداخل** بين العناصر غير الزخرفية، ويجب أن تبقى كل العناصر داخل عرض الشاشة. اختبارات `test_forms` تفحص ذلك.
- **الشاشات الكبيرة** تتمدد مع النافذة عبر `fit_window` (مواصفات `FitControls`)، ويجب أن يكون ارتفاعها 17 سم أو أقل.
- **اسم العمود في القائمة** لا يكون فارغًا `AS [ ]`، وإلا ظهر الخطأ 3126.
- **السطر في الكود المولَّد** أقل من 1000 حرف.
- **النص الذي يضعه الكود وقت التشغيل** في عنوان أو قائمة يمر بـ `Tr(...)`، واسم عمود القائمة لا يساوي بعد ترجمته حقلًا في تعبيره، حتى لو كان مؤهلًا مثل `q.Cost`. وقائمة تعرض اسم حساب أو عميل أو مورد أو صندوق… تقرأ `[@Accounts] AS a` أو `[@Customers] AS c`… (`docs/39-English-Master-Data.md`، `docs/40-English-Party-Names.md`). وبحث المستخدم يُضاف إلى SQL بعد `Tr` لا قبله.

**العملة في الشاشات:** الدالة `currency_pair` في `tools/forms.py` تضع `cboCurrency` و`txtRate` في أي شاشة مستند، والكود في `modCurrency`:
- `CurrencyReset`: يضع العملة الافتراضية للمستند.
- `CurrencyPicked`: يقترح المعامل عند اختيار العملة.
- `CurrencyChoice`: يتحقق من العملة والمعامل عند الحفظ.

## 6) الوصول إلى الشاشات والصلاحيات
- **القائمة الجانبية:** `NAV_ITEMS` في `tools/forms.py`.
- **مربعات الشاشة الرئيسية:** `LAUNCH_TILES`.
- **شاشة المحاسبة والمالية:** `HUB_TILES` في `tools/forms_accounting.py` (ومنها المندوبين وعمولاتهم).
- **مركز التقارير:** `OpenScreen "frmReportCenter", 0, "KEY"` يفتحه على تقرير محدد.
- **صلاحية كل شاشة:** `SCREEN_PERMISSIONS` في `tools/forms.py`، و`SCREEN_LIST` في `tools/schema.py`.
  - `OpenScreen` يرفض فتح شاشة غير مسموحة.
  - `ApplyNavPermissions` يعطّل أزرار ومربعات الشاشات الممنوعة ويلوّنها بالرمادي.

## 7) خطوات إضافة شاشة
1. **شاشة بيانات:** أضف `DataScreen` إلى `DATA_SCREENS`.
2. **أي شاشة أخرى:** اكتب `layout_x()` في `forms_*.py`، وأضفها إلى `all_forms()`.
3. **الصلاحية:** أضف الشاشة إلى `SCREEN_PERMISSIONS` وإلى `SCREEN_LIST`.
4. **طريق الوصول:** القائمة الجانبية، أو مربع في شاشة المحاسبة، أو زر في شاشة قريبة.
5. **السلوك:** في وحدة VBA مكتوبة يدويًا، بإجراءات من نوع `Public Sub XLoad(ByVal frm As Access.Form)`. كود الشاشة يستدعيها بسطر واحد.
6. **التوليد والاختبار:** `python3 tools/generate.py`، ثم اختبار يتأكد أن كل `frm!X` يستخدمه الكود موجود في الشاشة.
