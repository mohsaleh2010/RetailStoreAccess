# ملف الفاتورة السعودية الموقّع (المرحلة الثانية من فاتورة)

**الفكرة:** هذه المرحلة «ج1» من الخطة (`docs/43-Plan-EInvoicing-SA-EG.md`). تبني ملف الفاتورة الذي تشترطه هيئة الزكاة والضريبة والجمارك، وتحسب بصمته، وتوقّعه، وتنشئ رمز QR بتسعة حقول. **الإرسال للهيئة وتسجيل الجهاز في المرحلة «ج2»** (`docs/47-ZATCA-Onboarding-Sending.md`).

## 1) ما يُبنى لكل فاتورة بيع أو إشعار دائن
| الجزء | التفاصيل |
|---|---|
| **الملف** | صيغة UBL 2.1. نوعه: فاتورة 388، أو إشعار دائن 381 (فيه رقم الفاتورة الأصلية وسبب الإرجاع). مبسطة (0200000) أو ضريبية (0100000) |
| **البائع** | اسم المحل، والرقم الضريبي، والسجل التجاري، والعنوان الوطني: الشارع، ورقم المبنى، والرقم الإضافي، والحي، والمدينة، والرمز البريدي |
| **المشتري** | فارغ في المبسطة. في الضريبية: اسم العميل، ورقمه الضريبي، وعنوانه، وتاريخ التوريد |
| **الأسطر** | الكمية، ووحدة الهيئة (`ZatcaUnitCode`)، والسعر بدون ضريبة (حتى 4 خانات)، وخصم السطر، والصافي، والضريبة، والإجمالي |
| **الإجماليات** | الضريبة لكل فئة ونسبة، والصافي، والإجمالي |
| **طريقة الدفع** | نقدي 10، شبكة 48، تحويل 42، آجل 30 |
| **عدّاد المستندات (ICV)** | العدّاد الموجود منذ المرحلة الأولى |
| **بصمة المستند السابق (PIH)** | تبدأ بالقيمة التي تحددها الهيئة لأول مستند |
| **البصمة** | SHA-256 للملف بعد حذف ثلاثة أجزاء: التوقيع، وعنصر التوقيع، ورمز QR. تُحسب كما تحسبها الهيئة: تحويل الملف إلى الصيغة القياسية (C14N) ثم SHA-256 |
| **التوقيع** | ECDSA على المنحنى secp256k1 لبايتات البصمة، ببرنامج **OpenSSL** والمفتاح الخاص للجهاز. ومعه كتلة XAdES بالشهادة ووقت التوقيع |
| **رمز QR بتسعة حقول** | 1 اسم البائع، 2 الرقم الضريبي، 3 التاريخ والوقت، 4 الإجمالي، 5 الضريبة، 6 البصمة، 7 التوقيع، 8 المفتاح العام، 9 توقيع الشهادة |

**الحقول الناقصة:** قبل البناء يذكر البرنامج كل ما ينقص، مثل: رقم مبنى المحل 4 أرقام، أو الرمز البريدي 5 أرقام، أو الحي، أو بيانات العميل في الفاتورة الضريبية.

**ما لم يُدعم بعد:** الأصناف المعفاة أو ذات النسبة الصفرية. تحتاج «سبب الإعفاء» الذي تحدده الهيئة، والبرنامج يرفضها برسالة واضحة.

## 2) شاشة «إعداد ربط منصة فاتورة»
**أين:** الإعدادات ← الفاتورة الإلكترونية ← «إعداد الربط». تحتاج صلاحية إعدادات المحل.

| الحقل أو الزر | ما يفعل |
|---|---|
| **مسار OpenSSL** | فارغ = `openssl` من مسار النظام |
| **ملف المفتاح الخاص** | يبقى على جهاز آمن، ولا يُحفظ في قاعدة البيانات، بل مساره فقط |
| **شهادة الجهاز (CSID)** | تُلصق كما تصدرها الهيئة. تظهر تحتها الجهة المصدرة والرقم التسلسلي |
| **حفظ** | يُسجَّل في سجل التدقيق |
| **شهادة تجريبية** | **في البيئة التجريبية فقط.** ينشئ مفتاحًا وشهادة ذاتية بـ OpenSSL في مجلد `ZATCA` بجانب البرنامج، للتجربة قبل شهادة الهيئة |
| **ملف XML لفاتورة** | تكتب رقم فاتورة بيع، فيُنشأ ملفها الموقّع في مجلد التقارير لتفحصه بأداة الهيئة. **لا يغيّر الفاتورة ولا سلسلة البصمات** |

## 3) كيف تتأكد من الملف بأداة الهيئة
1. نزّل أداة الهيئة (Fatoora SDK) من بوابة المطورين في موقع الهيئة. تحتاج Java.
2. نفّذ:
   ```
   fatoora -validate -invoice "C:\...\Reports\ZATCA-رقم.xml"
   ```
3. النتيجة المطلوبة: البصمة والتوقيع ورمز QR وقواعد الهيئة مقبولة.
   - مع الشهادة التجريبية قد تحذّر الأداة من أن الشهادة غير صادرة من الهيئة، وهذا متوقع.

## 4) للمطوّر
| الملف | ما فيه |
|---|---|
| `src/vba/modZatcaXml.bas` | **دوال لا تقرأ البيانات:** `ZxInvoice`، `ZxParty`، `ZxLine`، `ZxTaxSubtotal`، `ZatcaInvoiceHash`، `ZatcaCertInfo` (قراءة الشهادة بنفسه)، `ZatcaExtensions`، `ZatcaQRCode`، `ZatcaSignedDocument`، `Base64Decode`، `Utf8Decode` |
| | **من البيانات:** `ZatcaDocumentXml`، `ZatcaDataProblem` |
| | **التوقيع:** `ZatcaSignHash` (OpenSSL)، `ZatcaBuildSigned` |
| | **المرحلة ج2:** `ZatcaPrepareDocument` يوقّع المستند مرة واحدة ويقدّم السلسلة داخل معاملة تقفل `Settings.LastInvoiceHash` |
| | **الشاشة واختبار `TestZatcaXml`** |
| `modZatcaData` (مولَّدة) | نصوص كتلة التوقيع بمسافاتها كما تعيد الهيئة حسابها، من `tools/zatca_xml_reference.py` عبر `tools/gen_zatca.py` |
| `tools/zatca_xml_reference.py` | النسخة المكتوبة بـ Python |

**الحقول الجديدة:**
- `Settings.OpenSslPath` و`ZatcaKeyFile` و`ZatcaCertificate`؛
- `EInvoiceXml` (الملف الموقّع) على الفواتير والمرتجعات.

**كيف تُحسب البصمة بقص النص:** الملف يُكتب **مباشرة بالصيغة القياسية (C14N)**:
- إعلانات الأسماء والخصائص بترتيبها القياسي؛
- لا عناصر فارغة مختصرة؛
- الرموز الخاصة مكتوبة كما تكتبها C14N.

لذلك حذف الأجزاء الثلاثة من النص يساوي ما تفعله الهيئة: الحذف من شجرة الملف ثم التحويل القياسي. يُفحص ذلك في الاختبارات بمكتبة lxml.

**مصدر قوالب التوقيع:** نصوص التوقيع وترتيب العناصر مأخوذة من حزمة npm `zatca-sdk` 0.1.2 (رخصة MIT، © 2026 aashahin). ملفاتها تجتاز أداة الهيئة وبيئتها التجريبية. أداة الهيئة نفسها لم تكن متاحة من بيئة التطوير.

**إصلاح وُجد أثناء العمل:** في VBA يسبق الضرب القسمة الصحيحة. فكتابة `Len(s) \ 4 * 3` تعني `Len(s) \ 12`، والمصفوفة تصغر عن الشهادة. صُحّحت إلى `(Len(s) \ 4) * 3`، وأُضيفت القاعدة واختبار يمنع تكرارها.

## 5) الاختبارات
`tests/test_zatca_xml.py`:
- **الملف بالصيغة القياسية:** يطابق C14N من مكتبة lxml، لفاتورة مبسطة وإشعار دائن ضريبي.
- **البصمة:** تساوي «الحذف من الشجرة ثم C14N ثم SHA-256» قبل التوقيع وبعده.
- **التوقيع:** توقيع OpenSSL يُتحقق منه بمكتبة cryptography على بايتات البصمة.
- **الشهادة:** قراءتها تطابق مكتبة cryptography (الجهة المصدرة، والرقم التسلسلي، والمفتاح العام، والتوقيع).
- **رمز QR:** حقوله التسعة صحيحة.
- **كتلة التوقيع:** النص المحسوب والنص المكتوب في الملف بالمسافات نفسها.
- **VBA في LibreOffice = النسخة المكتوبة بـ Python حرفًا بحرف:** الملف، والبصمة، وقراءة الشهادة، وكتلة التوقيع، ورمز QR، والملف النهائي.
- **السلسلة:** تُقفل قبل القراءة، والمستند يُوقَّع مرة واحدة.
- **الشاشة:** صلاحية الإعداد، وسجل التدقيق، والشهادة التجريبية في البيئة التجريبية فقط.

**داخل Access:** `TestZatcaXml` (ضمن `RunAllTests`) يفحص:
- صيغة السعر والكمية؛
- بصمة فاتورة نموذجية تساوي النسخة المكتوبة بـ Python؛
- أن البصمة لا تتغير بإضافة التوقيع ورمز QR؛
- ملف آخر فاتورة بيع؛
- التوقيع بـ OpenSSL إن وُجد مفتاح.

## 6) التثبيت والاختبار
1. **ثبّت OpenSSL** على جهاز الإرسال، مثل «Win64 OpenSSL Light» من Shining Light Productions، أو OpenSSL الذي يأتي مع Git for Windows. ثم ضع مساره في الإعداد أو في مسار النظام.
2. **استورد الوحدتين الجديدتين** `modZatcaXml` و`modZatcaData`.
3. **استبدل** `modEInvoice` و`modTestAll` والوحدات المولَّدة (الصف 42 في `README.md`). أو أعد البناء بـ `BuildFrontEnd.vbs`.
4. شغّل `BuildSchema` ثم `BuildForms`.
5. **اكتب العنوان الوطني للمحل في الإعدادات:** الشارع، ورقم المبنى 4 أرقام، والرقم الإضافي، والحي، والمدينة، والرمز البريدي 5 أرقام، والرقم الضريبي.
6. افتح الإعدادات ← الفاتورة الإلكترونية ← «إعداد الربط»، ثم:
   1. «شهادة تجريبية»؛
   2. «ملف XML لفاتورة» واكتب رقم فاتورة.
7. شغّل `RunAllTests`، وفيه `TestZatcaXml`. بعد إنشاء الشهادة التجريبية يختبر التوقيع أيضًا.
8. **إن كانت عندك أداة الهيئة:** افحص الملف بـ `fatoora -validate` وأرسل لي النتيجة.
