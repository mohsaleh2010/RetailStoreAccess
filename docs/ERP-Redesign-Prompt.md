# برومبت إعادة تصميم واجهات نظام ERP (حسابات ومخازن) باستخدام MudBlazor

> انسخ كل ما تحت هذا السطر وألصقه في Claude Code وأنت داخل فولدر المشروع.

---

أنت مهندس واجهات أول متخصص في ASP.NET Core Blazor وMudBlazor، ولديك خبرة في أنظمة المحاسبة والمخازن العربية.

## السياق
- هذا المشروع نظام ERP للحسابات والمخازن، كان مبنيًا على Microsoft Access وتم تحويله إلى ASP.NET Blazor.
- المنطق يعمل، لكن التصميم الحالي سيئ وقديم وغير احترافي.
- المطلوب: إعادة تصميم **كل الشاشات** بمكتبة **MudBlazor** (أحدث إصدار مستقر) بشكل عصري واحترافي وموحّد، مع دعم كامل للعربية (RTL).

## قواعد صارمة طوال العمل
1. **لا تغيّر أي منطق عمل**: لا تعدّل الـ Services أو الـ Repositories أو الـ DbContext أو الحسابات أو الاستعلامات. التعديل في طبقة الواجهة فقط (ملفات .razor و.razor.cs الخاصة بالعرض و CSS).
2. إذا احتاجت شاشة تعديلًا بسيطًا في الكود الخلفي لكي تعمل مع MudBlazor (مثل إضافة دالة ترقيم صفحات)، **اسألني أولًا**.
3. استخدم **Plan Mode**: اعرض خطتك قبل كل مرحلة وانتظر موافقتي.
4. اعمل على فرع git جديد لكل مرحلة/دفعة، وبعد كل دفعة: `dotnet build` بدون أخطاء أو تحذيرات جديدة، ثم commit برسالة واضحة.
5. أزل Bootstrap وأي CSS قديم متعارض بعد اكتمال النقل، ولا تخلط مكتبات واجهات.
6. توقّف عند كل نقطة مكتوب عندها **⏸ توقف للمراجعة**.

## المرحلة 1: الجرد والتحليل (بدون أي تعديل)
1. اقرأ هيكل المشروع واعرف: إصدار .NET، نوع المشروع (Blazor Web App / Server / WASM)، وضع الـ render mode الحالي، ومكتبات الواجهة المستخدمة.
2. اعمل جردًا بكل الصفحات (`@page`) واكتبه في ملف `docs/ui-inventory.md` كجدول فيه: المسار، اسم الملف، الموديول (مبيعات/مشتريات/مخازن/حسابات/تقارير/إعدادات)، ونوع الشاشة من الأنواع التالية:
   - **A — بيانات أساسية (قائمة + إضافة/تعديل)**: أصناف، عملاء، موردين، مخازن، حسابات...
   - **B — حركة رأس وتفاصيل**: فواتير بيع/شراء، مرتجعات، تحويل مخزني، أذون صرف/إضافة، قيود يومية، سندات قبض/صرف.
   - **C — تقرير**: كشف حساب، جرد، حركة صنف، ميزان مراجعة، أرباح...
   - **D — لوحة/صفحة خاصة**: الرئيسية، تسجيل الدخول، الإعدادات.
3. اذكر أي ملاحظات: شاشات مكررة، مشاكل أداء واضحة (تحميل كل البيانات مرة واحدة)، شاشات بدون تحقق من المدخلات.

**⏸ توقف للمراجعة** — اعرض الجرد والملاحظات.

## المرحلة 2: الإعداد الأساسي ونظام التصميم
1. ثبّت MudBlazor: `dotnet add package MudBlazor`.
2. في `Program.cs`: `builder.Services.AddMudServices();` (مع إعداد Snackbar: الموضع أسفل اليسار، مدة 3 ثوانٍ).
3. في `_Imports.razor`: `@using MudBlazor`.
4. في `App.razor`: أضف خط **Cairo** من Google Fonts (أوزان 400/600/700)، و`_content/MudBlazor/MudBlazor.min.css`، و`_content/MudBlazor/MudBlazor.min.js`، واجعل `<html lang="ar" dir="rtl">`.
5. تأكد من وجود وضع تفاعلي: في Blazor Web App ضع `@rendermode="InteractiveServer"` على `<Routes>` و`<HeadOutlet>` (أو ما يناسب نوع المشروع).
6. أنشئ ملف `Theme/ErpTheme.cs` يحتوي على `MudTheme` ثابت:
   - **PaletteLight**: Primary `#1E3A5F` (كحلي)، Secondary `#0F9D8A` (أخضر مزرق)، Tertiary `#F2A541`، Success `#2E7D32`، Error `#C62828`، Warning `#ED6C02`، Background `#F5F7FA`، Surface `#FFFFFF`، AppbarBackground `#1E3A5F`، DrawerBackground `#FFFFFF`، TextPrimary `#1F2937`.
   - **PaletteDark**: نسخة داكنة متناسقة (Background `#0F172A`، Surface `#1E293B`، Primary `#60A5FA`، Secondary `#2DD4BF`).
   - **Typography**: الخط الافتراضي `Cairo, sans-serif`، وأحجام عناوين معتدلة (H4 للعنوان الرئيسي للصفحة، H6 لعناوين الكروت).
   - **LayoutProperties**: `DefaultBorderRadius = "8px"`، `DrawerWidthRight = "260px"`.
7. أعد بناء `MainLayout.razor`:
   - `MudRTLProvider RightToLeft="true"` يحيط بكل شيء.
   - `MudThemeProvider` (مربوط بـ IsDarkMode مع حفظ الاختيار في LocalStorage)، `MudPopoverProvider`، `MudDialogProvider`، `MudSnackbarProvider`.
   - `MudAppBar` بارتفاع منخفض (Elevation 0): زر القائمة، اسم النظام، اسم الشركة/الفرع، بحث سريع عن شاشة، زر الوضع الليلي، قائمة المستخدم.
   - `MudDrawer` قابل للطي (Mini variant على الشاشات الصغيرة) يحتوي `NavMenu` مبنيًا بـ `MudNavMenu` و`MudNavGroup` مجمّعًا حسب الموديول، بأيقونات Material مناسبة لكل بند.
   - `MudMainContent` بـ padding موحّد و`MudContainer MaxWidth="MaxWidth.ExtraExtraLarge"`.
8. ملف `wwwroot/css/erp.css` صغير للإضافات فقط (أرقام بخط tabular-nums، صفحة الطباعة، إلخ).

**⏸ توقف للمراجعة** — شغّل التطبيق وخذ لقطة شاشة للتخطيط العام بالوضعين الفاتح والداكن.

## المرحلة 3: المكونات المشتركة (`Components/Shared`)
ابنِ هذه المكونات قبل أي شاشة، وكل مكون موثّق بتعليق قصير ومثال استخدام:

| المكون | الوظيفة |
|---|---|
| `PageHeader` | عنوان الصفحة + `MudBreadcrumbs` + منطقة أزرار إجراءات (RenderFragment) + وصف اختياري. |
| `EntityGrid<TItem>` | غلاف على `MudDataGrid`: بحث سريع، فلاتر أعمدة، ترتيب، ترقيم صفحات، تحميل من السيرفر عبر `ServerData` عند توفره، تصدير Excel، Dense + Hover + Striped، رسالة "لا توجد بيانات" وحالة تحميل `MudProgressLinear`. |
| `EntityDialog` | قالب `MudDialog` للإضافة/التعديل مع `MudForm` وتحقق، وأزرار حفظ/إلغاء ثابتة. |
| `LookupField<T>` | `MudAutocomplete` لاختيار صنف/عميل/مورد/حساب بالكود أو الاسم، مع عرض الرصيد أو السعر بجوار الاسم. |
| `InvoiceLinesEditor` | جدول بنود الحركة: إضافة سطر، تعديل داخل الجدول، حساب الكمية × السعر − الخصم + الضريبة تلقائيًا، إجماليات في الأسفل، تنقّل بالكيبورد (Enter للخانة التالية، سطر جديد تلقائي بعد آخر خانة، Delete لحذف السطر). |
| `FilterPanel` | لوحة فلاتر التقارير: من تاريخ/إلى تاريخ (`MudDateRangePicker`)، اختيارات، زر "عرض" وزر "مسح". |
| `MoneyText` / `QtyText` | تنسيق المبالغ (جنيه، خانتان عشريتان، لون أحمر للسالب) والكميات. |
| `StatusChip` | `MudChip` بلون حسب الحالة (مسودة/مرحّل/ملغي/مدفوع جزئيًا). |
| `ConfirmDialog` | تأكيد الحذف والترحيل بنص واضح. |
| `StatCard` | كارت إحصائية للوحة الرئيسية (رقم كبير + عنوان + أيقونة + نسبة تغيّر). |
| `EmptyState` | حالة فارغة بأيقونة ونص وزر إجراء. |

أضف خدمة اختصارات كيبورد عامة: **F2 حفظ**، **F3 بحث**، **F4 جديد**، **Esc إغلاق النافذة**، **Ctrl+P طباعة**.

**⏸ توقف للمراجعة**

## المرحلة 4: ثلاث شاشات تجريبية (المرجع)
أعد تصميم شاشة واحدة من كل نوع (اقترح أنت الأنسب من الجرد، مثلًا: قائمة الأصناف، فاتورة البيع، كشف حساب عميل) حسب القوالب:

**قالب A — بيانات أساسية**
`PageHeader` (زر "إضافة جديد" Primary) ← شريط بحث وفلاتر ← `EntityGrid` بأعمدة أساسية فقط + عمود إجراءات (تعديل/حذف بأيقونات) ← الإضافة والتعديل في `EntityDialog`.

**قالب B — حركة رأس وتفاصيل**
`PageHeader` (رقم المستند + `StatusChip` + أزرار: حفظ، ترحيل، طباعة، جديد) ← `MudPaper` للرأس في `MudGrid` (التاريخ، العميل عبر `LookupField`، المخزن، طريقة الدفع، ملاحظات) ← `InvoiceLinesEditor` ← كارت ملخص الإجماليات ثابت على الجانب (Sticky) على الشاشات الكبيرة، وأسفل الجدول على الصغيرة. التركيز التلقائي على أول خانة.

**قالب C — تقرير**
`PageHeader` ← `FilterPanel` قابل للطي ← كروت ملخص صغيرة (إجمالي مدين/دائن/رصيد) ← `EntityGrid` للنتائج ← تصدير Excel وطباعة.

**قالب D — لوحة رئيسية**
صف `StatCard` ← رسوم بيانية (`MudChart`) للمبيعات الشهرية وأعلى الأصناف ← جداول مختصرة (آخر الفواتير، أصناف تحت حد الطلب).

بعد التنفيذ: شغّل التطبيق، افتح كل شاشة في المتصفح، وخذ لقطات شاشة (فاتح/داكن، وعرض شاشة 1440px و768px)، وراجعها بنفسك وأصلح أي مشكلة في المحاذاة أو RTL قبل عرضها عليّ.

**⏸ توقف للمراجعة** — لن ننتقل للتعميم قبل اعتمادي لهذه الشاشات الثلاث.

## المرحلة 6: النقل على دفعات
1. قسّم الشاشات المتبقية من `docs/ui-inventory.md` إلى دفعات حسب الموديول: المبيعات ← المشتريات ← المخازن ← الحسابات ← التقارير ← الإعدادات.
2. لكل دفعة: فرع git، خطة مختصرة، تنفيذ عبر skill `mudblazor-erp-ui`.
3. يمكنك تشغيل **وكلاء فرعيين (Subagents)** على التوازي، كل واحد على موديول مختلف، بشرط أن يلتزم كل منهم بالـ Skill ولا يعدّل المكونات المشتركة؛ أي تعديل مطلوب في مكون مشترك يرجع لك أنت لتنفيذه مرة واحدة.
4. بعد كل دفعة: build، لقطات شاشة لكل صفحة، تحديث عمود "الحالة" في `docs/ui-inventory.md`، commit.

**⏸ توقف للمراجعة بعد كل دفعة**

## المرحلة 7: التشطيب
1. صفحة طباعة للفواتير والتقارير بـ CSS طباعة مستقل (A4 و80mm للكاشير) بعيدًا عن MudBlazor.
2. إزالة Bootstrap وملفات CSS القديمة غير المستخدمة.
3. مراجعة أداء: الجداول الكبيرة بـ `ServerData` أو `Virtualize`.
4. مراجعة شاملة نهائية بواسطة وكيل فرعي مستقل لم يشارك في التنفيذ، يمر على كل الشاشات بقائمة المراجعة ويكتب تقريرًا بالمشاكل.
5. ملف `docs/ui-changelog.md` بملخص ما تغيّر.

ابدأ الآن بالمرحلة 1 فقط.
