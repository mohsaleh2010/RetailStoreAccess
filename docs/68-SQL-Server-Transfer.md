# نقل البيانات إلى SQL Server، والمطابقة، والاتصال بالخادم (المرحلة 5ب)

**الفكرة:** المرحلة الثانية من الخطة 5 (`docs/51`). كل الخطوات من داخل البرنامج، من شاشة واحدة:
1. الاتصال بالخادم.
2. تجهيز القاعدة بالسكربت (`docs/67`).
3. نقل البيانات من ملف Access.
4. مطابقتها.
5. ربط البرنامج بالخادم، أو الرجوع إلى ملف Access.

لا يلزمك SQL Server Management Studio.

> **مهم:** الربط بالخادم في هذه المرحلة **للتجربة فقط، وعلى نسخة**. تعديلات الكود ليعمل البرنامج كاملًا على الخادم في **5ج**، ومنها النسخ الاحتياطي من الخادم وحفظ السجلات الجديدة. ملف Access يبقى كما هو، وزر «الرجوع إلى Access» يعيدك إليه.

## 1) الشاشة (`frmSqlServer`)
**من أين:** «نسخة احتياطية» ← زر **«SQL Server»**.

**الصلاحية الجديدة:** «قاعدة SQL Server: الاتصال ونقل البيانات وتشغيل البرنامج على الخادم» (`SQL_SERVER`)، لمدير النظام فقط.

| الحقل | المعنى |
|---|---|
| **الخادم** | مثل `.\SQLEXPRESS` على نفس الجهاز، أو `اسم-الجهاز\SQLEXPRESS` في الشبكة، أو عنوان خادم سحابي |
| **قاعدة البيانات** | `RetailStore` افتراضيًا |
| **الدخول** | **حساب Windows** (المفضّل: لا كلمة مرور تُحفظ)، أو **مستخدم SQL Server** باسم وكلمة مرور |
| **برنامج التشغيل (ODBC)** | تعرض الشاشة ما هو مثبّت على الجهاز، الأحدث أولًا. المفضّل **ODBC Driver 18 for SQL Server** (مجاني من Microsoft) |
| **ملف سكربت القاعدة** | `sql\RetailStore_Schema.sql` بجانب ملف البرنامج، أو اختره بـ «استعراض» |

**إعدادات الاتصال تُحفظ في ملف البرنامج على كل جهاز**: الخادم، والقاعدة، والمستخدم، وبرنامج التشغيل. كلمة المرور لا تُحفظ في الإعدادات. مع «مستخدم SQL Server» تبقى في ربط الجداول فقط، كما يفعل Access.

## 2) الأزرار بالترتيب
| الزر | ما يفعله |
|---|---|
| **اختبار الاتصال** | يتأكد أن الخادم يرد والقاعدة موجودة، ويعرض عدد جداول البرنامج الناقصة فيها |
| **تجهيز القاعدة** | يشغّل السكربت جزءًا جزءًا. القاعدة الجديدة تُنشأ جداولها، والموجودة تُرقّى ولا تُحذف بياناتها. شغّله بعد كل تحديث للبرنامج |
| **نقل البيانات** | ينسخ كل جداول ملف Access إلى الخادم بأرقامها نفسها (أرقام الفواتير والعملاء والقيود...). التفاصيل تحت الجدول |
| **مطابقة البيانات** | لكل جدول يقارن بين Access والخادم: **عدد السجلات**، و**مجموع كل حقول المبالغ**، و**أول حرف من كل نص**، لكشف العربي الذي وصل علامات «?». يعرض جدولًا: مطابق / مختلف |
| **التشغيل على الخادم** | يطابق أولًا، ولا يربط إن وُجد جدول مختلف. ثم يربط كل جداول البرنامج بالخادم بلا DSN، ويحفظ مسار ملف Access للرجوع. أغلق البرنامج وافتحه |
| **الرجوع إلى Access** | يعيد ربط الجداول بملف Access الذي كان قبل الخادم. ما سُجّل على الخادم بعد الربط لا يظهر فيه |

**تفاصيل «نقل البيانات»:**
1. **يحذف كل ما في قاعدة الخادم أولًا.** النقل يكون مرة واحدة قبل العمل على الخادم، أو من جديد للبدء من ملف Access.
2. يوقف شروط الخادم وعلاقاته مؤقتًا، وينسخ البيانات.
3. يعيد فحص كل سجل بكل الشروط والعلاقات، ويتوقف برسالة واضحة إن وجد بيانات قديمة لا تحققها.
4. يُرفض إذا كان البرنامج يعمل على الخادم.

## 3) عند فتح البرنامج
إن كان البرنامج مربوطًا بالخادم والخادم لا يرد، تظهر في شاشة الدخول رسالة: «لا يرد خادم البيانات ...، تأكد من تشغيل الخادم والشبكة»، مع نص الخطأ. لا يظهر خطأ Access عام.

## 4) التجربة الكاملة (على جهازك، على نسخة)
1. خذ **نسخة احتياطية** من `RetailStore_BE.accdb`، واعمل على نسخة من ملف البرنامج.
2. ثبّت **SQL Server Express** و**ODBC Driver 18 for SQL Server**.
3. أنشئ القاعدة: `CREATE DATABASE RetailStore COLLATE Arabic_100_CI_AS;`، أو اتركها لزر «تجهيز القاعدة» إن كانت موجودة.
4. انسخ مجلد `dist\sql` بجانب ملف البرنامج، ثم شغّل `BuildFrontEnd.vbs` أو استورد الوحدات (القسم 6).
5. «نسخة احتياطية» ← «SQL Server»، ثم بالترتيب:
   1. اختبار الاتصال.
   2. تجهيز القاعدة.
   3. نقل البيانات: يعرض المطابقة بعده، وكل الجداول «مطابق».
   4. التشغيل على الخادم.
6. أغلق البرنامج وافتحه. تصفّح العملاء والأصناف والتقارير. **لا تسجّل عملًا حقيقيًا قبل 5ج.**
7. ارجع: «SQL Server» ← «الرجوع إلى Access».

## 5) للمطوّر
| الملف | ما فيه |
|---|---|
| `src/vba/modSqlServer.bas` (جديدة) | `SqlLiteral`، `ServerConnect`، `SplitSqlBatches`، `InsertBatchSql` (بلا قاعدة بيانات، ولها مرآة Python)؛ `ServerExec` / `ServerValue` (استعلام مباشر Pass-through عبر DAO)؛ `RunSchemaScript`؛ `CopyTable` (دفعات من 200 سجل مع `IDENTITY_INSERT`)؛ `TransferAllData`؛ `CompareTable` / `CompareAllData`؛ `LinkToServer` / `LinkToAccess`؛ `CheckServerAtStartup`؛ الشاشة؛ والاختبار `TestSqlServer` |
| `modBuildSchema` (مولَّدة) | `SchemaTableList()`: جداول البرنامج بالترتيب |
| `modSecurityScreens` | `LoginLoad` يفحص الخادم قبل أول قراءة للإعدادات |
| `tools/forms_sql.py` (جديد) | الشاشة؛ وزر «SQL Server» في شاشة النسخ الاحتياطي |
| `tools/sql_transfer_reference.py` (جديد) | مرآة Python؛ قاعدة «خادم» على SQLite من أجزاء السكربت نفسها، بـ LIKE على طريقة SQL Server وبمقارنة المبالغ مقرّبة لأربع خانات مثل MONEY |

**القيم إلى T-SQL:**
- نعم/لا: 1 أو 0. Access يخزّن «نعم» −1.
- التاريخ: `'yyyymmdd hh:nn:ss'`، يُقرأ بالطريقة نفسها مهما كانت لغة الخادم.
- النص: `N'...'` بمضاعفة الفاصلة العليا.
- الأرقام: بنقطة عشرية مهما كانت إعدادات الجهاز.

## 6) التثبيت
1. **الأسهل:** أعد تشغيل `dist\tools\BuildFrontEnd.vbs`.
2. **أو يدويًا:**
   - استورد `modSqlServer` (جديدة).
   - استبدل `modSecurityScreens` و`modTestAll` والوحدات المولَّدة (`modBuildSchema` و`modBuildForms` و`modAppData` و`modLang` و`modLangData*`).
   - Debug ← Compile، ثم `BuildSchema` (للصلاحية والشاشة الجديدتين) ← `BuildForms`.
3. **`TestSqlServer`** (أو `RunAllTests`): يختبر الأجزاء التي لا تحتاج خادمًا (القيم، والاتصال، وتقسيم السكربت، وقائمة الجداول، وملف البيانات الحالي).

## 7) الاختبارات (`tests/test_sql_transfer.py`)
- **المرآة:** القيم، ونص الاتصال بحساب Windows وبمستخدم، وتقسيم السكربت الحقيقي عند `GO`، ودفعة الإدخال.
- **الوحدة نفسها في LibreOffice:** تعطي النتائج نفسها التي تعطيها المرآة.
- **النقل:** بيانات الاختبار والبيانات التجريبية كاملة (790 سجلًا) تُنقل إلى قاعدة لها شروط الخادم وقيمه الافتراضية وعلاقاته، ثم:
  - كل العلاقات سليمة، والمطابقة نظيفة، والعربي كما هو؛
  - المطابقة تكشف اسمًا عربيًا صار «?????» وسعرًا زاد هللة؛
  - شروط الخادم ترفض سعرًا سالبًا.
- **الكود:**
  - ترتيب النقل: إيقاف الشروط، ثم الحذف، ثم النسخ، ثم إعادة الفحص؛
  - الربط بعد مطابقة نظيفة فقط؛
  - فحص الخادم في شاشة الدخول قبل أي قراءة؛
  - لا تُحفظ كلمة مرور في الإعدادات؛
  - كل أدوات الشاشة موجودة؛ والصلاحية لمدير النظام فقط.

**لم يُختبر بعد:** الاتصال الفعلي بالخادم ونقل بياناتك الحقيقية. هذا على جهازك (القسم 4)، وأرسل لي أي رسالة خطأ.
