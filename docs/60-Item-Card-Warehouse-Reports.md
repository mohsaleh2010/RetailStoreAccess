# كارت الصنف وتقارير المخازن والجرد لكل مخزن

**الفكرة:** هذه المرحلة «2د» من الخطة (`docs/51-Plan-Opening-Warehouses-Treasury-Reps-SQL-Web.md`)، بعد المخازن (`docs/57`) والتحويل بينها (`docs/58`) وسندات الصرف والاستلام (`docs/59`).
- كان تقرير «حركة منتج» **بالكمية فقط**، ولكل المخازن معًا، ولا يذكر الجهة.
- الآن: **كارت الصنف** بالكمية **والقيمة**، لمخزن واحد أو لكل المخازن، ومعه الجهة. وثلاثة تقارير مخازن جديدة. ولكل مخزن جرده المفتوح.

## 1) كارت الصنف (`ITEM_CARD`)
**من أين:**
- شاشة «المنتجات» ← زر **«كارت الصنف»**: يفتح مركز التقارير على الكارت، والصنف مختار، والفترة من أول السنة المالية حتى اليوم.
- أو «التقارير» ← «كارت الصنف (الكمية والقيمة لكل مخزن)».

**الاختيارات:** الفترة، و**الصنف** (إلزامي)، و**المخزن** (اختياري؛ فارغ = كل المخازن).

**الأعمدة:**

| العمود | ما فيه |
|---|---|
| التاريخ، الحركة، المستند | تاريخ الحركة ونوعها ورقم مستندها |
| المخزن | مخزن الحركة |
| الجهة / البيان | العميل في البيع ومرتجعه، والمورد في الشراء ومرتجعه، والجهة في سند الصرف أو الاستلام، و**المخزن الآخر** في التحويل. غير ذلك: ملاحظات الحركة |
| وارد، منصرف، الرصيد | الكمية، والرصيد التراكمي بعد كل حركة |
| تكلفة الوحدة | التكلفة المسجلة على الحركة |
| قيمة الوارد، قيمة المنصرف، رصيد القيمة | الكمية × التكلفة، ورصيد القيمة التراكمي |

**السطر الأول: رصيد أول المدة** بالكمية والقيمة، وهو مجموع الحركات قبل بداية الفترة (في المخزن المختار).

**آخر التقرير:** رصيد أول المدة (كمية وقيمة)، والوارد والمنصرف خلال الفترة، و**الرصيد النهائي** (كمية وقيمة).

**لماذا رصيد القيمة صحيح:** كل خروج يُسجَّل بمتوسط التكلفة وقت الحركة، فرصيد القيمة = الكمية × متوسط التكلفة.

## 2) تقارير المخازن الجديدة
| التقرير | ما فيه | الاختيارات |
|---|---|---|
| **تقييم المخزون لكل مخزن** (`STOCK_VALUE_WAREHOUSE`) | لكل مخزن: حساب مخزونه (1400 أو 140000 + رقمه)، وعدد الأصناف، والكمية، والقيمة بالتكلفة، والقيمة بسعر البيع | لا شيء |
| **التحويلات بين المخازن بالطريق** (`TRANSFERS_IN_TRANSIT`) | كل تحويل أُرسل ولم يُستلم: الرقم، وتاريخ الإرسال، ومن مخزن، وإلى مخزن، والقيمة، و**عدد الأيام بالطريق** | لا شيء |
| **فروقات الجرد المرحّلة لكل مخزن** (`STOCK_COUNT_DIFF`) | العجز والزيادة لكل صنف كما رُحّلا فعلًا، وقيمتهما | الفترة (تاريخ الجرد)، والمخزن اختياري |

**تقرير «أرصدة الأصناف لكل مخزن»** (`STOCK_WAREHOUSE`) صار يقبل اختيار **مخزن واحد**.

**اختيار المخزن في مركز التقارير:** قائمة **«المخزن»** جديدة، تعمل فقط مع التقارير التي تحتاجها. المخزن المختار يُطبع تحت عنوان التقرير، أو «كل المخازن».

## 3) الجرد لكل مخزن
- **قبل:** جرد مفتوح واحد في البرنامج كله.
- **الآن:** **جرد مفتوح واحد لكل مخزن**. تستطيع جرد المخزن الرئيسي والفرع في الوقت نفسه. محاولة فتح جرد ثانٍ لنفس المخزن تُرفض: «يوجد جرد مفتوح لهذا المخزن».
- شاشة الجرد تفتح على **الجرد المفتوح لمخزن المستخدم**، وإلا أحدث جرد مفتوح.
- **قائمة الجلسات** ومعلومات الجرد و**ورقة الجرد المطبوعة** تعرض **المخزن**.

## 4) للمطوّر
| الملف | ما فيه |
|---|---|
| `tools/queries.py` | `qryStockMoveParty` (الجهة الأخرى لكل حركة، اتحاد بحسب `ReferenceType`)، `ItemCardQuery` (المعامل الجديد `WarehouseID`، 0 = الكل)، `StockValueByWarehouseQuery`، `TransfersInTransitQuery`، `StockCountDiffQuery` (من حركات `STOCK_COUNT` المرحّلة)، و`StockCountQuery` صار فيه المخزن |
| `tools/forms.py` | التقارير الأربعة في `REPORTS`، وقائمة `cboWarehouse` في مركز التقارير، وزر «كارت الصنف» في المنتجات |
| `tools/reports_catalog.py`, `tools/reports_docs.py` | تخطيط التقارير الأربعة، والمخزن في ورقة الجرد |
| `src/vba/modScreens.bas` | حرفا الاختيار الجديدان: `W` = المعامل `WarehouseID` (0 = الكل)، و`w` = تصفية العمود `WarehouseID`. و`OpenArgs` = `"KEY|ProductID"` يختار الصنف |
| `src/vba/modPurchases.bas`, `modPurchaseScreens.bas` | جرد مفتوح لكل مخزن، والمخزن في شاشة الجرد |
| `src/vba/modWarehouses.bas` | الاختبار `TestStockReports` |

**قاعدة Access المتّبعة:** رقم الحركة في `ItemCardQuery` اسمه `MoveID`، لا `TransactionID`، لأن الاتحاد يربط `qryStockMoveParty` التي فيها `TransactionID` أيضًا، فيصبح الاسم في ترتيب الاتحاد مبهمًا.

## 5) الاختبارات
**`tests/test_item_card.py`** على قاعدة SQLite المحاكية:
- **الكارت لكل المخازن:** رصيد أول المدة بالكمية والقيمة، ثم الحركات، ورصيد القيمة = الكمية × المتوسط.
- **الكارت لمخزن واحد،** وعمودا الوارد والمنصرف بالكمية والقيمة.
- **الجهة:** المخزن الآخر في التحويل، والجهة في السند، والعميل في البيع.
- **قيمة الكارت = تقييم المخزن.**
- **التحويلات بالطريق** تختفي بعد الاستلام.
- **فروقات الجرد المرحّلة.**
- **فحوص الكود:** قائمة المخزن، والفتح من شاشة المنتج، والجرد لكل مخزن.

**`TestStockReports`** داخل Access، ضمن معاملة تُلغى:
- كارت الصنف لكل المخازن ولمخزن واحد، ورصيد أول المدة؛
- الجهة في التحويل؛
- تقييم المخزن، والتحويلات بالطريق؛
- جردان مفتوحان لمخزنين، ورفض جرد ثانٍ لنفس المخزن.

## 6) التثبيت والتجربة
1. **نسخة احتياطية** من ملف البيانات.
2. **استبدل** `modScreens` و`modPurchases` و`modPurchaseScreens` و`modWarehouses` و`modTestAll` والوحدات المولَّدة (الصف 55 في `README.md`). أو أعد البناء بـ `BuildFrontEnd.vbs`.
3. **شغّل بالترتيب:** `BuildQueries` ← `BuildForms` ← `BuildReports`، ثم `RunAllTests` (أو `TestStockReports`). لا جداول جديدة.
4. **التجربة:**
   1. «المنتجات» ← اختر صنفًا ← **«كارت الصنف»** ← «عرض التقرير»: رصيد أول المدة، والحركات، والرصيد بالكمية والقيمة.
   2. اختر **مخزنًا** في القائمة وأعد العرض: حركات هذا المخزن فقط.
   3. «التقارير» ← **«تقييم المخزون لكل مخزن»**.
   4. «التقارير» ← «التحويلات بين المخازن بالطريق».
   5. «الجرد»: افتح جردًا للمخزن الرئيسي، ثم اختر الفرع واضغط «جرد جديد»: يُفتح جرد ثانٍ. جرد ثالث للفرع يُرفض.
