# صلاحيات الشاشات، وحساب المبرمج، وتفعيل البرنامج

## 1) صلاحيات الشاشات لكل مستخدم (`frmUserScreens`)
**من أين تُفتح:** شاشة **المستخدمون**، زر **«صلاحيات الشاشات»**.

**كيف تعمل:**
1. اختر المستخدم.
2. فعّل **«صلاحيات شاشات خاصة بهذا المستخدم»**. تظهر كل شاشات البرنامج، ولكل شاشة:

| العمود | المعنى |
|---|---|
| **فتح** | الشاشة تظهر للمستخدم ويفتحها. إلغاؤه يحذف الشاشة من قائمته |
| **إضافة / حفظ** | سجل جديد، أو حفظ مستند جديد (فاتورة، سند، جرد...) |
| **تعديل** | تعديل السجلات المحفوظة. بدونه تُعرض للقراءة فقط |
| **حذف** | زر الحذف |
| **ما ينطبق عليها** | الإجراءات الموجودة في الشاشة. الفواتير والسندات لا تُعدَّل ولا تُحذف بعد الحفظ، والتقارير فتح وعرض فقط |

3. اضغط **حفظ**. تسري الصلاحيات من الدخول التالي للمستخدم.

**تفاصيل:**
- **نقطة البداية:** تبدأ القائمة من صلاحيات دور المستخدم. وزر **«من صلاحيات الدور»** يعيدها كما كانت.
- **الرجوع لصلاحيات الدور:** إلغاء «صلاحيات شاشات خاصة» ثم حفظ.
- **مدير النظام والمبرمج** يفتحان كل الشاشات بكل الصلاحيات دائمًا، ولا يمكن تقييدهما.
- **صلاحياتك أنت:** لا يمكنك تغييرها بنفسك.
- **الصلاحيات الخاصة** تبقى من **دور** المستخدم في شاشة الأدوار، لأنها ليست شاشات: تقارير الأرباح، وتعديل سعر البيع، والخصم الأعلى، والبيع بالسالب، والأرقام المالية في لوحة التحكم.
- **أين يُطبَّق المنع:**
  - القائمة الجانبية ومربعات الشاشة الرئيسية: الشاشة الممنوعة تظهر معطلة.
  - شاشات البيانات (المنتجات، العملاء، الموردون، المصروفات، الصناديق...): زر جديد، والتعديل، وزر الحذف.
  - حفظ كل مستند: البيع بأنواعه، والمرتجعات، والسندات، والمشتريات، والمخزون، والجرد، والخزينة.

## 2) حساب المبرمج
- **مستخدم واحد أعلى من مدير النظام:**
  - اسم المستخدم: `developer`.
  - يملك كل الصلاحيات دائمًا.
  - **لا يظهر في شاشة المستخدمين** ولا في قائمة صلاحيات الشاشات، فلا يستطيع المدير تعديله أو تعطيله.
- **الإنشاء:** تنشئه `BuildSchema` مرة واحدة، و**تطلب كلمة مروره عند الإنشاء**، فلا يوجد أبدًا حساب مبرمج بدون كلمة مرور.
  - إذا ضغطت إلغاء لا يُنشأ الحساب، ويُطلب مرة أخرى في التشغيل التالي.
  - لتغيير كلمة المرور لاحقًا: ادخل بحسابه، ثم من الشاشة الرئيسية غيّر كلمة المرور.
- **اسم المحل:** في **الإعدادات** يظهر للمبرمج فقط خيار **«السماح لمدير النظام بتغيير اسم المحل»**.
  - **إن لم يُفعَّل (الافتراضي):** يكون اسم المحل (عربي وإنجليزي) للقراءة فقط لمدير النظام وغيره، ويغيّره المبرمج وحده.
  - **إن فُعِّل:** يغيّره مدير النظام أيضًا.
- **توليد أكواد التفعيل** لأجهزة العملاء (البند التالي).

## 3) تفعيل البرنامج على جهاز محدد (الحماية من النسخ)
### الفكرة
- **رقم الجهاز:** لكل جهاز رقم بالشكل `XXXX-XXXX-XXXX-XXXX`. هو بصمة SHA-256 من:
  - الرقم التسلسلي للوحة الأم.
  - رقم المعالج.
  - الرقم التسلسلي لقرص Windows.
- **نسخ الملفات لجهاز آخر لا يفيد:** هناك رقم الجهاز مختلف، فيرفض البرنامج العمل.
- **كود التفعيل:** `XXXXX-XXXXX-XXXXX-XXXXX`. يحسبه البرنامج من رقم الجهاز ومن **سر** لا يعرفه إلا المبرمج (`LICENSE_SECRET` في `modActivation`). بدون السر لا يمكن صنع كود صحيح.
- **مكان الحفظ:** يُحفظ التفعيل في ملف البيانات (جدول `Activations`). في الشبكة يُفعَّل كل جهاز يعمل عليه البرنامج بكوده.

### الدخول على جهاز غير مفعّل
| المستخدم | ماذا يحدث |
|---|---|
| **المبرمج** | يدخل دائمًا (لتجهيز الجهاز) |
| **مدير النظام** | تفتح له شاشة **تفعيل البرنامج** ولا يصل للبرنامج قبل التفعيل |
| **أي مستخدم آخر** | رسالة: البرنامج غير مفعّل على هذا الجهاز، ثم يُغلق |

### خطوات التفعيل
1. يفتح مدير النظام **الإعدادات ← تفعيل البرنامج**، أو تفتح الشاشة وحدها عند دخوله.
2. يضغط **«نسخ الرقم»** ويرسل رقم الجهاز للمبرمج.
3. المبرمج يدخل بحسابه على نسخته، ويفتح **تفعيل البرنامج**، ثم يكتب رقم جهاز العميل في **«للمبرمج: توليد كود تفعيل»** ويضغط **«توليد الكود»**.
   - **بديل:** `python3 tools/activation_reference.py رقم-الجهاز`.
4. يكتب المدير الكود ويضغط **«تفعيل هذا الجهاز»**.

- **قائمة الأجهزة المفعّلة:** في الشاشة نفسها، مع زر **«إلغاء تفعيل الجهاز المحدد»**، لجهاز قديم مثلًا.
- **متى يتغير رقم الجهاز:** عند تغيير اللوحة الأم أو المعالج، أو **إعادة تهيئة قرص Windows**. عندها يحتاج الجهاز كودًا جديدًا.

### قبل تسليم البرنامج لعميل (مهم)
1. **غيّر السر:** في `modActivation` غيّر `LICENSE_SECRET` إلى نص سري طويل خاص بك، واحتفظ به.
   - كل الأكواد التي تصدرها تعتمد عليه.
   - إذا غيّرته لاحقًا تبطل الأكواد القديمة.
2. **سلّم ملف ACCDE وليس ACCDB:** File ← Save As ← Make ACCDE.
   - في ACCDE لا يمكن قراءة الكود ولا تعديله، فيبقى السر مخفيًا ولا يمكن حذف فحص التفعيل.
   - مع `InstallUserMode` (تعطيل مفتاح SHIFT) لا يصل المستخدم لأدوات Access.
3. **احتفظ بنسختك ACCDB** للتطوير، ولتوليد الأكواد.

> **حدود الحماية بصراحة:**
> - ملف Access ليس برنامجًا مُجمَّعًا بالكامل.
> - الحماية أعلاه (ACCDE، ورقم الجهاز، والسر، وتعطيل SHIFT) تمنع النسخ العادي ومحاولات المستخدم العادي.
> - لا تمنع شخصًا محترفًا مصممًا على كسرها. هذا حد كل برامج Access.

## الجداول والحقول الجديدة (يضيفها `BuildSchema`)
| الجدول / الحقل | المحتوى |
|---|---|
| `Screens` | كل شاشة: اسمها، وقسمها، وصلاحية الدور التي تفتحها، وهل فيها إضافة / تعديل / حذف |
| `UserScreens` | شاشات المستخدم صاحب الصلاحيات الخاصة |
| `Activations` | الأجهزة المفعّلة: رقم الجهاز، والكود، واسم الجهاز، والتاريخ، ومن فعّله |
| `Employees.IsDeveloper` / `Employees.CustomScreens` | المبرمج / المستخدم له شاشات خاصة |
| `Settings.AllowAdminCompanyName` | السماح لمدير النظام بتغيير اسم المحل (للمبرمج فقط، الافتراضي لا) |

## التثبيت
| # | الخطوة |
|---|---|
| 1 | **نسخة احتياطية** |
| 2 | **الطريقة الأسهل:** أعد تشغيل `dist\tools\BuildFrontEnd.vbs`، فيستورد كل الوحدات ومنها الجديدة `modActivation` |
| 3 | **أو يدويًا:** استورد `modActivation`، واستبدل `modBuildSchema`، `modBuildRelations`، `modBuildForms`، `modAppData`، `modCommon`، `modForms`، `modPOS`، `modPurchaseScreens`، `modCash`، `modSecurity`، `modSecurityScreens`، `modTestSecurity`، ثم Debug ← Compile، ثم `BuildSchema` ← `BuildRelations` ← `BuildForms` |
| 4 | `BuildSchema` **تطلب كلمة مرور المبرمج**: اكتبها واحتفظ بها |
| 5 | ادخل بـ `developer`، ثم الإعدادات ← تفعيل البرنامج: ولّد كود هذا الجهاز وفعّله، وقرر خيار اسم المحل |
| 6 | `RunAllTests` (اختبار `TestSecurity` يشمل الآن الشاشات والمبرمج والتفعيل) |

> **تنبيه للأجهزة الحالية:** بعد هذا التحديث **لا يعمل البرنامج على أي جهاز قبل تفعيله**، باستثناء دخول المبرمج. فعّل كل جهاز قبل أن يبدأ عليه البيع.
